DOCUMENTATION

Wire it, then talk to it.

Everything the browser sends is a documented binary frame. Here is the pinout, the protocol and the build.

QUICK START

01

WIRE

Signal into GPIO26 (ADC0), grounds tied together. A 1 kΩ + 10 µF low-pass turns PWM into something the ADC can read.

02

FLASH

Build and upload the Pico SDK firmware, then check that the browser sees the handshake.

03

CONNECT

Open the console in Chrome or Edge, pick the Pico serial port, press Run — connecting alone streams nothing.

WIRING

ANALOG INPUTS

Raw 12-bit codes, 0 to 4095. No attenuation stage in front of the ADC.

PROTOCOL V2

A frame on the wire

VER1 B TYPE1 B SEQ2 B PLEN2 B PAYLOADPLEN bytes CRC-162 B

COBS framed, 0x00 delimiter, CRC-16/CCITT-FALSE over the header and payload.

MESSAGEDIRECTIONNOTES
HELLO_REQ / HELLO_RSPhost to device, device to hostVersion, channel counts and limits handshake
SET_CONFIGhost to deviceMode, channel mask, rate, count, trigger mode, edge, source and level
CAPTURE_REQhost to deviceAsks for one frame; the host re-requests each frame while running
CAPTURE_DATAdevice to hostFlags, trigger index, sample count and interleaved 12-bit codes
ACK / NACKdevice to hostAcknowledges a SET_CONFIG with the configuration it actually applied

BUILD & FLASH

pio run -e pico                 # build the firmware
pio run -e pico -t upload       # flash the Pico
cd tests/host && make test      # host-side capture tests

Pico SDK, native — no Arduino framework. The panel is an addon; the browser is the product.
